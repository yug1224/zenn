_Type-Aware Linting Stable と React Compiler Support を載せた。TypeScript 7 への一本化はこれから_

## はじめに

こんにちは。ぷーじ（[@yug1224](https://x.com/yug1224)）です。

2026年7月に Type-Aware Linting が Stable になり、8月には Oxc が React Compiler Support を出しています。

https://oxc.rs/blog/2026-07-22-type-aware-linting-stable.html

https://oxc.rs/blog/2026-08-18-react-compiler-support.html

以前の記事では、Type-Aware を Alpha として入れていて、終わりに `oxlint --type-aware --type-check` 一発で lint と型チェックが完結するかもしれない、と書いていましたが、今回、Dress Code のフロントエンドには、この2つを載せました。

https://zenn.dev/dress_code/articles/d655cd7a43b936

この記事では、そのあとに入れたものと、TypeScript 7 への一本化はまだ先にしている話を紹介します。フルの typecheck を待たなくても、Lefthook の差分チェックで型エラーが手前で分かるようになったのは、個人的にはかなり嬉しい変化です。

公式ガイドは、CI で `tsc --noEmit` を置き換えられると書いていますが、同じ機能の CLI `--type-check` は experimental です。Dress Code では、早期検知用は oxlint、フルチェックは `tsc`、という棲み分けにしています。

https://oxc.rs/docs/guide/usage/linter/cli.html

:::message
早期検知は oxlint の `options.typeCheck` です。フルチェック（マージ前の正）は、今も各アプリの TypeScript 7 の `tsc`（`pnpm typecheck`）です。CI の typecheck ジョブは外していません。
:::

## Type-Aware が Stable になった

https://oxc.rs/docs/guide/usage/linter/type-aware

リポジトリルートの `oxlint.config.ts` で、`typeAware` と `typeCheck` をオンにしています。`typeAware` は lint が型を見るスイッチで、未処理の Promise の様な、見た目だけでは分からないものがここで落ちます。前回で Alpha として入れたのがこれです。

`typeCheck` は、同じ TypeScript program からコンパイラ診断も Oxlint 経由で出すスイッチです。lint の結果と型エラーが一度に並ぶので、手元では `tsc` を別待ちする感覚が薄くなります。

```ts
export default defineConfig({
  options: {
    // Type-Aware Linting Stable（oxlint-tsgolint@7）
    typeAware: true,
    // 早期検知用。フルの型検査の正は pnpm typecheck
    typeCheck: true,
    reportUnusedDisableDirectives: 'error',
  },
});
```

### フルの typecheck を待たずに、差分で型が分かる

pre-commit は Lefthook です。ステージした `src` 配下の `.ts` / `.tsx` だけを oxlint に渡しています。

```yml
# lefthook.yml（構成を簡略化した例）
lint:
  glob: 'src/**/*.{ts,tsx}'
  exclude:
    - '**/schema.d.ts'
    - '**/routeTree.gen.ts'
  run: pnpm oxlint --tsconfig ./tsconfig.json --fix --fix-suggestions {staged_files}
```

型を壊した `src` 配下の `.tsx` を `git add` して `git commit` すると、Lefthook の `lint` が oxlint を回したところで止まり、コミットは作られません。フルの `pnpm typecheck` はここでは走っていません。返ってくるのはステージしたファイルに対する lint と、`options.typeCheck` 経由のコンパイラ診断です。

マージ前の正は、今も CI の `pnpm typecheck` です。それでもコミットのたびにフルを待たなくても、差分チェックで型エラーが手前で分かるのは嬉しいです。

## React Compiler の lint を分割した

Oxc の React Compiler Support に合わせ、oxlint を 1.79.0 へ上げました。公式は Compiler 由来のルールを 22 本に増やし、旧 nursery の単一ルール `react/react-compiler` はカテゴリ別へ置き換える、と書いています。Dress Code では、この分割ルールへ移しています。

Dress Code では、壊れると困る correctness 相当の 11 本だけを個別に error にし、`react/incompatible-library` や restriction / suspicious / perf 系は明示的に off にしています。分割ルールは `'use no memo'` を見ないので、TanStack Table まわりのオプトアウトはこれまでどおり babel 側に残しています。

ビルド側の annotation は前回から変えていません。lint は、前回は jsPlugin で `eslint-plugin-react-hooks` を読んでいましたが、今回はこの分割ルールへ移しています。

https://zenn.dev/dress_code/articles/92dfb9206f50f3

transform の `oxc-transform-react` はまだ乗せていません。公式の preliminary benchmark では Babel より 10 倍速い、とのことですが、自社では測っていません。`@vitejs/plugin-react` への統合は [vitejs/vite-plugin-react#1419](https://github.com/vitejs/vite-plugin-react/pull/1419) 待ちです。Dress Code のメインアプリは `@vitejs/plugin-react-swc` に `vite-plugin-babel` を足しているので、そのまま差し替えられる話ではありません。

## TypeScript 7 への一本化はこれから

https://devblogs.microsoft.com/typescript/announcing-typescript-7-0/

型検査の正も、前回で入れた tsgo（Native Preview）から TypeScript 7 の `tsc` に置きました。プレビュー用の `@typescript/native-preview` は外しています。エディタ向けには、[TypeScript 7 の公式拡張](https://marketplace.visualstudio.com/items?itemName=TypeScriptTeam.native-preview)も出ています。

ただし TypeScript 7.0 は programmatic API を同梱していません。`import 'typescript'` を利用するツールの peer 用に、ルートへ TypeScript 5.9.3 を残しています。ワークスペースの `typescript.tsdk` も、まだこちらを見ています。

lint の `typeCheck` に一本化しなかったのは、速さの問題ではありません。見ているファイルの範囲が、まだ同じではないからです。`schema.d.ts` と `routeTree.gen.ts` は `pnpm typecheck` の対象のまま、oxlint 側は `ignorePatterns` で外しています。生成物を lint するとノイズになるための非対称で、`typeCheck` を足しただけでは埋まりません。

tsgolint と TypeScript 7 の `tsc` は、出る診断がずれることもあります。私たちは `@tanstack/react-query` / `query-core` を 5.101.4 にピンしたうえで、そのずれを既知差分として扱っています。ignore の非対称が残っているあいだは、マージ前の正は `tsc` です。

ピンは 2026年8月時点です。

| パッケージ      | バージョン | 置き場所                   |
| --------------- | ---------- | -------------------------- |
| oxlint          | `1.79.0`   | リポジトリルート           |
| oxlint-tsgolint | `7.0.2001` | リポジトリルート           |
| oxfmt           | `0.52.0`   | リポジトリルート           |
| TypeScript 7    | `7.0.2`    | 各アプリ                   |
| TypeScript 5    | `5.9.3`    | ルート（programmatic API） |

2026年8月18日に、`standandforce/dresscode-frontend` の PR Check で成功した run を 12 本見ました。ランナーは `self-hosted-linux-arm` です。数字はジョブ全体ではなく、本体ステップです。

`pnpm run lint:check` は `typeAware` と `typeCheck` 込みで、40秒前後です（38〜44秒、多くは 39〜42秒）。型の正の `pnpm typecheck` は 50秒前後です（典型 46〜52秒）。

typeCheck を足しても、lint が typecheck を飲み込むほどの差にはなっていません。一本化する判断は、この秒数より、見ている範囲と診断が揃うかの方が大きいと感じています。

## まとめ

Type-Aware Linting を Stable に載せ、React Compiler の lint を分割ルールへ移しました。フルの `pnpm typecheck` を待たなくても、Lefthook の差分チェックで型エラーがコミット前に分かるようになったのが、個人的にはいちばん嬉しい変化です。

次は TypeScript 7 への一本化です。ignore の非対称と `query-core` まわりのずれを、運用で抱えてよいか。programmatic API 待ちで残している TypeScript 5 を、どこまで寄せられるか。揃ったと思えたら、CI の `pnpm typecheck` を外して、lint の `typeCheck` に寄せたいと考えています。

同じ規模で Type-Aware Stable や React Compiler の lint、TypeScript 7 を触っている人がいたら、X で [`@yug1224`](https://x.com/yug1224) まで教えてください。typeCheck を `tsc` の代わりにしているか、まだ並べているか、比較できると嬉しいです。
